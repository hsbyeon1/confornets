# Multi-Conformation Benchmark Assets

`crpyticpocket`, `domainmotion`, `foldswitching`, `membrane`, and `ood60` were adapted from [bioemu_benchmarks](https://github.com/microsoft/bioemu-benchmarks). For these benchmarks, we directly use the provided structures, which are already trimmed and filtered to backbone atoms. `gpcr` and `kinases` structures were retrieved directly from the PDB and are therefore not trimmed or filtered. Our RMSD evaluation, however, filters all structures to backbone atoms in all cases.

> [!WARNING]
> Currently the codebase is limited to 2 references states per test case.

## Directory Layout

```
$benchmark/
  references.csv                    # source of truth for test cases
  test_cases/
    $test_case_name/
      query/
        {query_id}.json             # OF3p-compatible query definitions
      reference/
        XYZ.cif or .pdb
      align_metric_info.json        # optional, 0-indexed CIF-space ranges
  batch/                            # generated by preprocess.py
  msa/                              # generated by preprocess.py
```

## Required Files

* `references.csv` - Reference structure mapping (test_case -> PDB files). Defines the set of test cases for the benchmark.

* `test_cases/{tc}/query/*.json` - **Query definition for structure prediction** in OF3p JSON format.
  A test case must have **either exactly 1 query JSON** (shared across all references) **or
  one JSON per reference**, in which case the filename (without `.json`) must match the
  corresponding `pdbidchain_*` entry in `references.csv`. E.g. for a test case with references
  `6XR6_A` and `6XRG_A`, the queries are `query/6XR6_A.json` and `query/6XRG_A.json`.
  ```json
  {
    "chains": [
      {"molecule_type": "PROTEIN", "chain_ids": ["A"], "sequence": "..."}
    ]
  }
  ```

* `test_cases/{tc}/reference/` - Processed reference CIF/PDB files for evaluation

## Optional Files

* `test_cases/{tc}/align_metric_info.json` - Defines alignment and metric residue ranges for local evaluations.
  ```json
  {
    "queries": {
      "5HT1B": {
        "alignment_resid_ranges": [[0, 200], [258, 328]],
        "metric_resid_ranges": [[258, 296]]
      }
    },
    "references": {
      "6G79_S": {
        "alignment_resid_ranges": [[0, 249]],
        "metric_resid_ranges": [[186, 221]]
      }
    }
  }
  ```
  If the file doesn't exist, the full sequence is used for all entities.

## Residue Range Convention

All ranges in `align_metric_info.json` use **0-indexed, end-exclusive** (Python slice convention):
- `[0, 200]` means residues 0 through 199 (i.e. `sequence[0:200]`)
- All ranges are in CIF coordinate space (no conversion needed at load time)

## Configuration (`config.yaml`)

* `consistent` - Whether conformation labels `i` and `j` have consistent meaning across test cases (e.g., active/inactive for kinases).
